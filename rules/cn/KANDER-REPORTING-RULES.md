# 完成报告格式

仅在 `rules.reporting=true` 时加载. 优先级与加载流程见 `KANDER-AGENTS.md`. 只规定汇报形式, 不新增 Git、审核或任务组门禁; 不适用步骤写 N/A.

- 非看板任务结束, 一句话说目标、完成情况、实际 commit 状态和分支; 非 Git 任务写「无提交, 分支不适用」.

## 完成报告

- 任务卡进入 `done/`, `archived/`, `trash/`, 或阻塞留在 `working/` / `review/` 交回用户时, 按模板汇报一次; 推进中不发. 禁用自由格式或一句完成/阻塞替代.
- 8 个字段不省略、不合并, 无内容写 `无` 或 `N/A`.

  结束方式写末行 `任务卡最终状态`, 取 `done`, `archived (<结果>)`, `trash`, `working (阻塞)` 或 `review (阻塞)`.

- 没进 `done/` 时, `任务` 写卡片当前状态目录下的绝对路径; `交付`, `验收`, `验证`, `审核`, `收尾` 只写实际完成项, 未做写 `未执行` 加原因. 未完成也不得留空、省行或换格式.
- 阻塞汇报在 `未处理问题` 里逐项列剩余工作、阻塞原因、解除条件, 并写分支和 worktree 保留现状.

  终止汇报另写用户授权的结论 (`cancelled`, `duplicate`, `wontfix`) 和原因, `duplicate` 指向替代卡.

- 结束者按模板汇报; 换会话、接管不免除, 组级汇总不替代单卡汇报.
- 验证只写实际结果, 失败、未执行、环境阻塞不得写成通过. 最终提交用完整 40 位 SHA. 适用收尾均成功可写"均完成", 异常逐项说明.
- 未处理问题列已知缺陷、验证缺口、后续任务, 同一根因只算一次.

  仅 `rules.review=true` 或用户明确要求本次完整审核时另按 `KANDER-REVIEW-RULES.md` 分类记审核项, 不因此加载关闭的审核模块.

  采用安全审核超时时附发送时间和超时时间.

```markdown
# 看板任务完成报告

- 任务: [<task-id> - <标题>](<done 下任务入口绝对路径>)
- 交付: <用户可观察结果和关键改动>
- 验收: <已完成数>/<总数>; <逐条自检结论或用户接受的例外>
- 验证: <实际命令和结果; 失败或未执行项的原因, 影响和替代证据>
- 审核: <PM, CSA, Hacker, QA 的 reviewer, 状态和摘要; 审核期间修复>
- 收尾: <完整 SHA | N/A>; <集成结果 | N/A>; <主树同步, worktree, 分支, 临时审核文件, `kander check` 均完成或逐项异常>
- 未处理问题 (<N>): <无; 或逐项写 `[来源或类别][档位或状态] 问题; 影响: ...; 理由: ...`; 超时项附发送时间和超时时间>
- 总结: <一句话总结>; 代码分支: <代码最终所在分支 | N/A>; 任务卡最终状态: <done | archived (<结果>) | trash | working (阻塞) | review (阻塞)>
```
