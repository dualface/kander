# 任务建卡引导

## 创建与确认

仅对尚未选择执行方式的新 Bug 或功能需求提供引导. 已由 `start`、`resume` 或 `notify` 接续的任务及用户指定的现有卡, 继续执行原卡, 不重复询问或另建卡. 用户已明确选择走看板或直接执行时, 直接按所选流程执行, 不重复询问. 纯问答、只读排查、文档或配置微调、发布和合入不触发建卡引导.

完成分析与实施计划后一次性提供选项:

```text
- 确认计划并走看板 (建卡并启动)
- 确认计划, 不走看板, 在本会话直接做
- 调整计划
```

上述选项用数字编号, 但不得与其他问题的序号重复.

- 选 `确认计划并走看板 (建卡并启动)` 同时授权计划、开发与看板流程, 不再确认开工.

  单卡依次执行 `kander new`、按已确认计划填写完整契约、按 `KANDER-KANBAN-RULES.md`「建卡后自审」完成自审与适用的独立审卡并修正、`kander pick <task-id>`、`kander start <task-id>`. 启动与跟踪责任按 `KANDER-KANBAN-RULES.md`「领取, 启动与协调」执行, 讨论 Agent 不再实现已委派的卡.

  仅在 `rules.task_groups=true` 且 `rules.git=true` 时, 按需读取 `KANDER-TASK-GROUP-RULES.md` 拆分和编排. 任务组关闭时按已确认的独立单卡契约执行, 不自动拆组或加载关闭模块.

- 选 `确认计划, 不走看板, 在本会话直接做` 按项目规则直接实施, 不建卡.
- 选 `调整计划` 时修改计划, 尚不建卡或启动.
