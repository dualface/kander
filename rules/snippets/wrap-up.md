**Executing Agent Wrap-Up**

- On a wrap-up notice, the executing agent first moves back to `working/` with the ID/epoch-bound move command, then confirms per `snippets/git-integrate.md` "Integration and Cleanup" that its changes are in the card's integration target. For direct integration, the check is `git merge-base --is-ancestor` with the final group HEAD plus the notice's statement that this card's changes are included. For a PR, the check is the merged criteria and the `source_commit`/`rebased_base` mapping given in the notice. Never judge ancestry with the pre-rebase SHA. If not satisfied, preserve the working state and report to the orchestrator.
- Once satisfied, delete this card's worktree, local task branch, and applicable remote task branch, without touching the group worktree or branch. In distributed mode (every v2 client), the remote branches to delete are this card's own, every branch below `refs/heads/kander-task/<project-id>/<task-id>/` that was pushed for any generation: list them with `git ls-remote --heads origin 'refs/heads/kander-task/<project-id>/<task-id>/*'` and delete all of them, those of earlier generations included, never another card's branch. Keep the immutable evidence refs below `refs/heads/kander/` and run the completion below from another checkout of the same project (`snippets/commands/dispatch.md` "Distributed wrap-up evidence"). Complete the summary's review and wrap-up parts (role conclusions or N/A, applicable rounds, final commit, group branch and integration target results). Publish records through the controlled update entrance before completion; a card in `done/` takes no further update. Run the completion command from the dispatch prompt, `kander move <task-id> done --result completed --dispatch-id <id> --execution-epoch <epoch> --delivery-commit <source_commit>`, and the targeted `kander check <task-id>`. The delivery commit is the `source_commit` of the wrap-up evidence, not this card's own final commit; read it from `intent.evidence.wrap_up.git.source_commit` in the output of `kander dispatch show <task-id> <dispatch-id>` (it equals `intent.base`; in distributed mode it is readable once `kander dispatch prepare` ran), or `source_commit` in `kander show --document dispatches/<dispatch-id>/integration.json <task-id>`. A wrap-up completion takes no `--disposition`: `dispatches/<dispatch-id>/integration.json` is read-only evidence, not a disposition artifact. Kander refuses either mistake with `board.dispatch_evidence_invalid` and names the expected `source_commit`. Report per the applicable `KANDER-REPORTING-RULES.md` template or the user's format. End the turn and keep the interactive CLI session waiting for the dismiss decision.
- The orchestrator does not modify the delivery, acceptance, and verification records written before the card moved into `review/`.
