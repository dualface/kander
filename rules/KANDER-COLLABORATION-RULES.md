# 交流与协作规则

## 交流与格式

- 图表宽度不超 100 英文字符; 超出则单元格内换行.
- 用户选项从 `1` 编号, 写清动作和结果; 只回编号即有效. 其他编号须与用户选项明显区分.

## 工作原则

- 选最小且可证实方案. 分析架构, 边界与根因; 结论须有证据.
- 新功能先查复用或扩展机会. 沿用周边风格.
- 不覆盖, 回退或清理用户改动.
- 阻塞切分, 验证或集成时保留现场并报告.
- 稳定的架构, API 和长期规则写入仓库文档.
- 在 `AGENTS.md` 中维护仓库文档索引.

## 用户维护文件

- 项目声明由用户手动维护的文件, Agent 禁改.

## 安全

- 凭据只能经环境变量, secret manager 或仓库约定的 gitignored secret 文件注入.
- 禁把真实 token, 凭据, 敏感服务地址或本机状态写入仓库, 日志, 测试 fixture, dry-run 或发布输出.
