### PM-01 — high — TUI 偏好写回把项目覆盖的 `tui` 值写进作用域 `config.json`

- **claim**: Observed
- **证据**:`internal/tui/cmd.go:69` 用 `loadPrefs()` 初始化 App;`internal/tui/prefs.go:20-26` 的 `loadPrefs` 读的是 **合并后** 配置 `config.Load(true)`;`internal/tui/prefs.go:29-36` 的 `savePrefs` 在 `config.Update` 回调里无条件执行 `cfg.TUI = value`,`value` 来自 App 的五个字段;`internal/tui/options_panel.go:537-546` `persistUI()` 用 `p.app.Columns/MinColumnWidth/Theme/RefreshSecs/Model.Single` 组装该值;`internal/tui/options_panel.go:457-460` `persistNow()` 与 `options_panel.go:511` `save()` 在 **任意分区**(interface/execution/review/rules,`options_panel.go:452-454`)提交时都会先调用 `persistUI()`;`internal/tui/options_form.go:711-714` 与 `internal/tui/app.go:150`(`saveColumns` → `prefs.go:63-67`)是另外两条同源入口。
- **违反的契约**:卡 2 USER_DECISIONS「所有写入路径(`Save`/`Update`/`SaveIfUnchanged`、doctor 修复、TUI 保存、安装向导)以未合并的作用域配置为读-改-写基底,覆盖文件中的值不得反向写入作用域 `config.json`」;ACCEPTANCE「…TUI 选项面板保存只写作用域 `config.json`…作用域 `config.json` 中不含覆盖文件独有的值」;EXPECTED_OUTCOME「TUI 选项面板加载的是作用域配置(不含覆盖)」。本次范围内新增的 `rules/KANDER-AGENTS.md:19`「Writes … only update the scope `config.json`. Overlay values are never written back.」同样与实现相冲突。
- **失败场景**:项目根提交 `.kander-config.json` = `{"tui": {"theme": "dark", "columns": 5}}`(`tui` 在 `internal/config/overlay.go:22-33` 的允许键内)。用户在该项目内启动 TUI:`loadPrefs` 取到合并值 → `app.Theme="dark"`、`app.Columns=5`;随后只要按一次列数快捷键,或在选项面板任一分区按 Enter 保存,`savePrefs` 就把 `dark`/`5` 写进作用域 `config.json`。该值此后在所有其他项目乃至全局生效,且用户没有任何提示。首次安装后 `tui/cmd.go:108` 自动打开 interface 分区,同一条路径会把覆盖值直接写进新建的作用域配置。
- **为什么现有测试没发现**:`internal/tui/options_test.go:683-716` `TestOptionsSaveLeavesOverlayIsolated` 的覆盖文件只写了 `kanban_agent`,断言的也只是 `kanban_agent`/`Reviewers`,没有任何 `tui` 键,因此这条写回路径不被覆盖。
- **最小修复**:让偏好写回以作用域配置为基底——在 `savePrefs` 的 `config.Update` 回调里以回调收到的作用域 `cfg.TUI` 为基底,只写入用户本次实际改动的字段(或另设 `loadScopePrefs()` 供写路径做差异比较),显示仍用合并值;并在 `TestOptionsSaveLeavesOverlayIsolated` 的覆盖文件里加入 `tui` 键。

### PM-02 — medium — 覆盖文件里使用旧平铺 `review_stages` 会让该项目下所有读配置的命令报错

- **claim**: Observed
- **证据**:`internal/config/overlay.go:205-210` `mergeOverlayRaw` 只对 **作用域** 原始 JSON 调用 `normalizeScopeReviewStages`,覆盖侧原样进入 `deepMerge`;`internal/config/overlay.go:44-58` 对同键的两个 object 递归合并;`internal/config/review_stages.go:79-85` 对档名与角色同层的结果直接报错。而本次范围新增的文档 `docs/custom-agents.md:84`、`AGENTS.md:51`、`rules/KANDER-REVIEW-RULES.md:330` 都明写「旧平铺 `{role: mode}` 仍然合法」。
- **失败场景**:作用域 `config.json` 由 kander 自身写出(`Save` 后必为两档,见 `review_stages_test.go:174-211`),项目提交 `.kander-config.json` = `{"review_stages": {"PM": "required"}}`。合并结果为 `{large:…, small:…, PM:…}` → `NormalizeReviewStages` 报 `review_stages 同时含档名与角色: PM, large`。此后该项目内 `kander config`、`kander start`、`kander review`、TUI 等一切经 `config.Load` 的命令全部失败,且错误信息指向用户从未同时写过的两类键,难以自解。`internal/config/overlay_test.go` 只覆盖了「作用域平铺 + 覆盖两档」,反方向无测试。
- **最小修复**:`mergeOverlayRaw` 在 `deepMerge` 前对 `overlay["review_stages"]` 同样调用 `NormalizeReviewStages`(与作用域侧对称),并补一条「覆盖为平铺、作用域为两档」的合并测试。

### PM-03 — medium — doctor 的缺档回填在「其余字段已规范」的配置上不落盘,并报告为「无变化」

- **claim**: Observed(别名与判定路径)/ Inferred(具体触发配置的相等性)
- **证据**:`internal/config/repair.go:141` `fillMissingReviewStageScales(provided)`;`provided` 来自 `repair.go:100` `asObject(raw)`,而 `internal/config/config.go:638-641` 的 `asObject` 是类型断言、返回同一个 map,因此 `repair.go:166` `provided["review_stages"] = normalized` **就地改写了 `raw`**;`repair.go:74` 随后用 `reflect.DeepEqual(raw, normalized)` 判断「文件是否已经是修复后的样子」,基准已被污染。该等值判断本身是既有语义(`repair_test.go:43-46`「second repair must not rewrite」证明规范文件上它必然为真)。
- **失败场景**:取一份 kander 自己写出的规范 `config.json`(doctor 或 Save 之后),手工删掉 `review_stages.small` 这一档。再跑 `kander doctor`:`fillMissingReviewStageScales` 把 `raw["review_stages"]` 就地补成两档,于是第 74 行判定「与修复结果一致」→ 不备份、不写盘、`result.Changed=false`,`internal/menu/doctor_repair.go:31-33` 打印「config.json is unchanged」。但磁盘上 `small` 档仍然缺失,下次 `Load` 时 `small` 全部退化为 `auto`(`review_stages.go:150-168`),与 doctor 当场返回并展示的 cfg(`small` = `large` 的副本)不一致,且反复运行 doctor 永远修不好。既有测试 `repair_test.go:125-150` 用的是缺大量键的最小配置,`DeepEqual` 必为假,因此漏检。
- **最小修复**:`fillMissingReviewStageScales` 不要就地改 `provided`——先深拷贝 `raw["review_stages"]` 再规范化(或把规范化结果只写进 `root`,不回写 `provided`);补一条「除 `review_stages` 缺一档外其余均为规范值」的 doctor 测试,断言 `result.Changed` 为真且文件被改写。
