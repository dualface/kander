# Kander

[English](README.md) | [简体中文](README-CN.md) | **日本語**

[![Kander - 複数 AI Agent のカンバン調整](docs/star-please.png)](https://github.com/dualface/kander)

一人でカンバンを使って複数の AI Agent をスケジュールする。

![Kander ワークフロー](docs/workflow-ja.svg)

## 1. クイックスタート

実行には Git と、Codex、Claude、Grok、Cursor、Pi のうち少なくとも 1 つが必要です。

**macOS** — Homebrew でインストールします：

```sh
brew install dualface/tap/kander

kander
```

**Linux** — バイナリを直接ダウンロードします：

```sh
ARCH=$(uname -m); [ "$ARCH" = x86_64 ] && ARCH=amd64; [ "$ARCH" = aarch64 ] && ARCH=arm64
curl -fsSL "https://github.com/dualface/kander/releases/latest/download/kander-linux-${ARCH}.tar.gz" | tar xz

./kander
```

**Windows** — [Releases](https://github.com/dualface/kander/releases) から `kander-windows-amd64.zip` をダウンロードし、展開して `kander.exe` を実行してください。

初回起動時にまだインストールされていなければ対話ウィザードが始まります。インストールが完了すればすぐに使えます。

4 ステップで始められます:

1. Agent セッションを新規に開き、そこで要件やタスクを議論し、目標と受け入れ条件を明確にします。Agent の Plan モードの利用を推奨します。
2. タスクが確定すると、Agent がカンバンフローでタスクを起動するか確認します。承認すればタスクは自動的に起動します。
3. 要件が複数ある場合は、要件ごとにステップ 1-2 を繰り返し、継続的にタスクを手配・起動します。
4. コマンドラインインターフェースでタスクの状態を確認します:

```sh
kander
```

![ターミナルカンバン](docs/kanban-screenshot-01.png)

> 上図のカンバンの内容は私の実プロジェクト [https://quicktui.ai](https://quicktui.ai) のものです。QuickTUI はコンピュータ上のさまざまな Agent をリモート操作するツールで、iOS/Android/macOS/Linux/Windows に対応し、無料で使えます。

さらに詳しく: スライド [タスクを効率的に進める方法](docs/how-to-advance-tasks-efficiently-ja.pdf) (PDF) を参照してください。

## 2. GitHub 連携

プロジェクトを GitHub リポジトリに紐づけるには [GitHub CLI](https://cli.github.com/)（`gh`）が必要です。Kander はトークンを要求・読み取り・保存せず、`gh` が管理する認証情報をそのまま利用します。

端末ボードで `g` を押すと、GitHub Issue の一覧がオーバーレイで開きます。

## 4. 変更履歴

### v0.7.2 — 2026-09-16

- グローバルルールのインストール先が `~/.agents/kander` になりました。旧来の場所は使いません。アップグレード後はインストーラーを一度実行し、ルールのエントリを新しいパスに向けてください。
- `kander check delivery` と `kander check overlap` を追加しました。どちらも Git を直接解析し、カンバンを必要とせず、通常の Git ワークツリーで動作します。終了コードは `0` が対応不要、`1` が指摘あり、`2` が引数エラーです。
- TUI のチャットボックスに、カンバン Agent とは独立した Agent とモデルの設定が付きました。
- ボードと詳細ビューの更新を UI goroutine の外に移し、増分サマリーキャッシュから読み込むようにしました。大きなボードの描画が目に見えて速くなります。
- オーケストレーターセッションはカード 1 枚でも実行できます。複数カードの計画に限定されなくなりました。
- ルール: 各分冊を Agent 向けの条項だけに絞り、ツールの仕組みは `docs/` に移しました。エントリファイルは各セッションが最初に行うことだけを示し、残りは `KANDER-LOADING-RULES.md` に委ねます。

### v0.7.1 — 2026-09-15

- インストール時にバイナリを自動でコピーします。Y/N の確認は起動時のみになり、インストールのコピー手順と混同しません。

### v0.7.0 — 2026-09-15

- レビューの役割を **PMQA** と **Security** に統合しました。まだ開いている旧 4 キーのバッチは従来の役割のまま動作し、Options パネルは旧レビューキーに移行のヒントを表示します。1 回でまとめてレビューしたいプロジェクト向けに、統合役割も選べます。
- ターミナルボードのチャットボックスから、カードを作らずに Agent セッションを開始できます。
- 空のボードではウェルカムオーバーレイを開き、`kanban/` が無ければ `kander init` を提案し、スコープ設定が無ければ Options を開きます。
- すべての確認ダイアログが同じキー規約に従います。
- Markdown 詳細ビューが vim のモーションに対応しました。

### v0.6.2 — 2026-09-14

- バイナリのグローバルな場所へのコピーを任意にしました。インストーラーは任意のグローバルコピーの意味を説明し、選択したエントリを使用します。

### v0.6.1 — 2026-09-14

- インストール時にパッケージマネージャーの実行ファイルリンクを正しく解決します。

### v0.6.0 — 2026-09-14

- **GitHub 連携。** `kander issue repo` が正規のリポジトリ識別子を解決します。`kander issue list` / `show` で issue を読み、ボードで `g` を押すと issue 一覧がオーバーレイで開きます。issue はバックログカードとして取り込め、`kander issue triage` が引き継ぎセッションを開始し、完了した結果は issue に書き戻されます。Kander はトークンを要求も読み取りも保存もせず、`gh` が管理済みの資格情報だけを再利用します。`kander doctor` は GitHub CLI の状態を報告します。
- **Pi** が Codex、Claude、Grok、Cursor に並ぶ組み込み Agent として加わり、レビューにも対応します。組み込み Agent はバージョン付きの埋め込み JSON 定義になり、起動 argv、ペインへの送信、終了コマンド、セッションフック、レビュー呼び出しを宣言します。カスタム Agent は自分でレビューテンプレートを宣言する必要があります。
- **ターミナル定義。** tmux と herdr は宣言的な定義から動き、単一のバックエンドインターフェースの背後にまとまりました。新しいターミナル一覧コマンドが利用可能な定義を報告し、適合性を確認し、バックエンドの選択順序を示します。
- **テーマ。** Tide、Dusk、Slate を含む 6 つの名前付きテーマを、設定と Options パネルから選べます。値はトゥルーカラーに固定です。
- **Options パネル。** プロジェクトオーバーレイを継承と復元付きで編集し、カードの規模ごとに Reviewer を設定し、Tab でタブを切り替え、インターフェース言語を即時に適用し、キャンセル時に元へ戻します。運用系コマンドは完全な設定を必要とするようになりました。
- **狭いターミナル。** 列がタブ列に変わり、スマートフォン幅のウィンドウでもボードを使えます。
- `kander orchestrate` が複数カードの計画を起動します。`kander subscribe --watch` はタスクグループ外のカードも監視します。
- 状態に応じたタスク操作のポップアップは `m` で開きます。`g` は issue 一覧に割り当てました。
- 永続ディスパッチはフェンス付きエポック期限で受理済みの作業を回復し、中断された引き継ぎの受領記録が失われなくなりました。
- タグ付きリリースを自動化し、Homebrew tap を同期します。
- ルール: カードの `SIZE` は行数ではなくタスクの難度で定義します。GitHub issue のルールセットを追加しました。オーケストレーターセッションは自分が開始したカードを監視し続けます。このリポジトリのタスクカードのタイトルは英語です。
