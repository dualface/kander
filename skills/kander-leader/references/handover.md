# Leader session handover

Use this procedure for a user-requested transfer from a live Claude Code leader with Herdr. When the recorded owner has already exited, follow the [ownership recovery rule](../SKILL.md#start-or-resume), reconcile outstanding operations, and restore supervision that is approved and active.

Before preparation and again before committing the transfer, the old leader reconciles its own execution duties against the board, any group checkpoint or lease, and current session work. Finish or separately hand off self-claimed cards, group coordination and direct execution under the applicable authorization and Kander recovery procedure. Verify the receiving owner took over each transferred duty. Defer while a background command, sub-agent, deployment, release or unanswered question still needs this session. From preparation onward, defer taking new execution duties. Supervise until the ownership commit, then forward late messages to the successor. Transfer leadership on the designated host and main worktree. Use the [state ownership rule](../SKILL.md#start-or-resume) for every transition. Address messages by the old and new session IDs so a duplicate or late message can be matched to its transfer.

1. **Old leader prepares.** Bring the [leader state](../SKILL.md#leader-state) up to date. Generate the successor UUID and write `Leader session: <old name> (<old id>), handing over to <new id> at <time>`. The old leader retains ownership until it commits the transfer in step 3.
2. **Old leader launches.** Use the project root and the current model, effort, and permission mode. Read the current terminal's labels with `hc get "$HC_TERMINAL_ID"`. Reuse its `herdr.space` and `herdr.tab`. If missing, find a live terminal rooted in this project, preferring a space with a tab named `leader`. Reuse that tab or create a tab ID with `tb` plus 32 lowercase hex digits. If no space is available, omit the labels and give the user `hc attach <new address>`.

   ```text
   hc run --bg --outlive-parent --name leader-<timestamp> --cwd <project-root> --label herdr.space=<space> --label herdr.tab=<tab> claude --model <model> --effort <effort> <permission-flags> --session-id <new-id> "<handover instruction>"
   ```

   Instruct the successor to invoke `/kander-leader`, read state, verify its UUID, prepare subscriptions, and prepare a patrol timer only if leader state records the patrol as approved and active. Before reporting ready, the successor must arrange its own state recheck within 10 minutes, independent of the old leader, its commit message and patrol timers. A timed wait in the successor session suffices. Keep the recheck active while awaiting commit or abort. If unavailable, report the gap and withhold readiness. Send a readiness acknowledgement with both session IDs, its session name, and the patrol job ID, or N/A when no patrol timer was prepared. While waiting for commit it performs setup only. A patrol firing during transfer follows the recorded owner. Forward any early idle notice to the old leader and recheck pending notices on taking ownership.
3. **Commit and wake the successor.** Within 10 minutes, verify the sender against the successor UUID in `~/.claude/sessions/*.json`. Under the lock, confirm the old owner and named successor, apply pending state changes, and record the new owner with a temporary “awaiting activation” entry containing both IDs and the old terminal address. Release the lock, cancel only the old patrol, and send `handover-committed <old-id> <new-id>` directly to the successor. Forward any late project messages to it.
4. **Confirm activation.** On the commit message or a direct state recheck, the successor verifies ownership and rechecks the recorded patrol state. If the patrol is approved and active, it ensures the timer runs; otherwise it cancels any patrol timer it prepared. It restores any other missing supervision that is approved and active, records activation, and replies `handover-active <old-id> <new-id>`. Duplicate commit messages repeat the acknowledgement. The old session verifies the acknowledgement and recorded owner, reports the completed transfer, then confirms its execution duties are settled before clearing its terminal for retirement. The successor tells active peers its name, verifies the old address and exact session using `hc ls`, `hc get`, and the old PID’s session file, then runs `hc kill <old address>` and `hc rm <old address>` after clearance. If the terminal is already gone, skip removal. Clear the temporary transfer entry after cleanup.
5. **Check the tab.** Where a Herdr tab exists, use `doc.get` for `herdr-app` over `hc connect --json`. Match the successor's tab ID in `value.spaces[].tabs[]`. If needed, change only its name to `leader` and call `doc.set` with the document and the version read. On conflict, reread before retrying. Verify the tab contains exactly one block whose `content.terminal` matches the successor. Report a failed check.

**Missing acknowledgement.** Recheck state within 10 minutes independently of patrol timers.

- Before commit, a live old owner may abort only its matching attempt, retire the verified attempted successor, and restore its patrol. Retry once at the next patrol or, without a timer, in the same session after reassessing readiness. Report if the second attempt fails.
- After commit, resend the missing message for the same IDs and reconcile against recorded activation. A live new owner continues even if the old session has exited. Once the old terminal is confirmed gone, clear the pending cleanup entry.
- If the **recorded owner** is confirmed dead before or after commit, return to the normal locked claim on the designated host. Recheck both session IDs and the transfer phase under the lock; the claimant may take ownership only if that same owner is still recorded and confirmed dead. Restore the patrol only if it is recorded as approved and active, and reconcile outstanding operations before resuming work. If identity or liveness is uncertain, preserve state and report the specific blocker. A timeout alone grants no takeover or terminal retirement.
