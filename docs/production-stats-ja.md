## ひとことで

1 人, 6 つの Agent, 90 日, 5 プロジェクト, **2,477 枚のタスクカード**. うち 1,727 枚にレビューの構造化記録がある. レビューは独立したレビュー実行で行われ, 89% はレビュアーが実行者と別の Agent. それ以前のカードはレビュー記録の形式が異なり, レビュー集計に含めない.

## 集計の定義

- **完了カード**: `kanban/done/` 配下のカード. ディレクトリカードと単一ファイルカードの両方を含む. `archived/` と `trash/` は含めない.
- **対象プロジェクト**: カードが 1 ~ 12 枚の他の 8 プロジェクト (合計 27 枚) は含めない.
- **期間**: カード ID の日付プレフィックスによる最初と最後の日付. 両端を含む.
- **レビューの構造化記録**: カードに `reviews/plan.json` がある. そのうち 1,471 枚に 1 回以上のレビュー実行があり, 残りはレビュー計画でレビュー対象外とされた.
- **レビューバッチ**: `reviews/batches/<バッチ>/disposition.json`. バッチ ID で重複を除く. タスクグループの複数カードにまたがるバッチは各カードに保存されるが, 1 回として数える.
- **レビュー実行**: 1 つのレビュー役割 (PMQA / Security など) による 1 回のレビュー. run ID で重複を除く. 実行回数には失敗や中断した実行も含む. 指摘は正常に終了した 2,647 回の実行からのみ取り, 「要対応の指摘があった実行」の割合はこれを分母とする.
- **要対応の指摘があったバッチ**: バッチ内のいずれかのレビュー実行が要対応の指摘を報告した.
- **要対応の指摘**: Kander はレビュー指摘を 6 段階に分ける. 上位 3 段階 (blocking / high / medium) は対応が必須で, レビュー報告の `FINDINGS` に入る. 下位 3 段階 (low / recommend / suggest) は提案のみで, `NON_BLOCKING` に入り, 要対応の指摘としては数えない. 2,182 件のうち 89% は medium で, 特定の条件でのみ失敗する欠陥や, 実装と食い違う文書, デッドコードなど.
- **実行したカード**: カードヘッダーの `OWNER` フィールド (古いカードでは `负责人`). 2,477 枚すべてにある.
- **実行モデル**: 実行者のセッションログで最も多く使われたモデル. セッションは, カードの `SESSION` フィールド, 対話型の Claude Code または Codex セッションでのそのカードの `kander pick`, そのカードを実行した Claude Code のサブエージェントのいずれかから特定する. レビュー済みカード 1,471 枚のうち 1,106 枚 (75%) でモデルを特定でき, 残りは「未特定」とした. Cursor の `default` は Cursor の自動モデル選択.
- **レビューラウンド**: 1 つのバッチで, 同じレビュー対象コミットに対して正常に終了したレビュー実行. 同じコミットに対する PMQA と Security は 1 ラウンドとする.
- **差し戻し**: そのカードに割り当てられた要対応の指摘が 1 件以上あるレビューラウンド. 割り当ては実行の `assignment.json` から取る. このファイルがない実行は, その指摘をレビューしたすべてのカードに割り当てる.
- **レビューモデル**: レビュー実行に記録された `model` フィールド. 当時の設定値で, `opus` のような別名も含む.
- **処置, 却下, 延期**: 各指摘の最後の処置記録を, その指摘を報告したレビュー実行に対して数える. 「却下」と「延期」は全処置を分母とし, 「要対応の指摘の却下」は blocking / high / medium のみを数える. 却下には事実の根拠またはユーザー判断の引用が必要で, ユーザー判断で置き換えられた指摘も含む. したがって却下率はレビュアーの誤検出率の上限である.
- **表にない行**: モデル表には, レビュー済みカードが 10 枚以上の実行モデルと, 1 つの役割で 20 回以上実行したレビューモデルだけを載せる. 「全体」の行はすべてのカードと実行を含む.
- **再現**: コード量以外のすべての数値は [`scripts/production-stats/`](../scripts/production-stats/README.md) のスクリプトで生成する.
- **カード数はスループットであり, 価値や難易度ではない.** プロジェクトごとにタスクの大きさが異なるため, 横比較には向かない.
- **モデル表はランキングではない.** 行ごとにカードの大きさ, プロジェクト, 役割, 期間が異なり, 90 日の間にモデルの割り当ても変わった.
